## MCP Agent Mail: source-level evidence

Pinned source: [`README.md`](https://github.com/Dicklesworthstone/mcp_agent_mail/blob/3fad5ec672869f81d2ca0a4c525dde004ac96f45/README.md), [`models.py`](https://github.com/Dicklesworthstone/mcp_agent_mail/blob/3fad5ec672869f81d2ca0a4c525dde004ac96f45/src/mcp_agent_mail/models.py), [`app.py`](https://github.com/Dicklesworthstone/mcp_agent_mail/blob/3fad5ec672869f81d2ca0a4c525dde004ac96f45/src/mcp_agent_mail/app.py), [`config.py`](https://github.com/Dicklesworthstone/mcp_agent_mail/blob/3fad5ec672869f81d2ca0a4c525dde004ac96f45/src/mcp_agent_mail/config.py), [`http.py`](https://github.com/Dicklesworthstone/mcp_agent_mail/blob/3fad5ec672869f81d2ca0a4c525dde004ac96f45/src/mcp_agent_mail/http.py).

The README describes an HTTP-only FastMCP asynchronous coordination server with identities, inbox/outbox, searchable thread history, voluntary file leases, and an agent/program/model/activity directory. It describes Git-backed human-auditable artifacts and SQLite indexing. It supports a shared project key or separate projects; cross-project contact handshakes can link agents.

The agent schema stores `task_description` (`max_length=2048`) and `last_active_ts`; no distinct `current_work` field or <=30-word cap was found. `fetch_inbox` docs explicitly recommend polling and incremental `since_ts` reads; fetching does not mark messages read. With notifications enabled (default false), message arrival touches a local per-project/per-agent signal file containing metadata; clients may watch using inotify, FSEvents or kqueue. This is host-local notification, not MCP network push.

`MessageRecipient` stores read and acknowledgement timestamps per recipient. `mark_message_read` and `acknowledge_message` preserve the original timestamp on repeat; acknowledgement also marks read. `ack_required` tells a recipient to acknowledge. `send_message` has no idempotency-key parameter and has a SQLite lock retry decorator; that does not establish request deduplication or exactly-once creation. The source stores messages in SQLite and writes Git archive copies. Atomicity across those stores, crash behavior, retention and backup guarantees were not established here.

For tool calls, `_authenticate_agent` resolves an agent in the selected project and requires that agent’s registration token (constant-time comparison), unless the MCP session is already bound to the identity. Project-admin operations accept a token belonging to an agent in that project. The HTTP layer supports a global bearer token and optional JWT/RBAC. Contact policies and handshakes govern communication between agents. These facts establish project-scoped application authorization; they do not by themselves establish hard isolation against hostile tenants sharing one server. The project selector is caller-supplied and deployment-level auth is global/configured by the operator.

The pinned LICENSE begins “MIT License (with OpenAI/Anthropic Rider).” The rider says no rights are granted to OpenAI, Anthropic, their affiliates or people acting for/on behalf of them without express prior written permission. It includes use such as copying, hosting, deploying, executing, testing and analyzing, and says it applies to derivative works. This is a report of the license text, not legal advice. See [full pinned LICENSE](https://github.com/Dicklesworthstone/mcp_agent_mail/blob/3fad5ec672869f81d2ca0a4c525dde004ac96f45/LICENSE).
